# 输出预览的算法与数据处理优化

日期：2026-10-30。运行环境：Factorio 2.1.24 / Space Age / mac-arm64。

本轮基线为上一轮分帧优化后的工作区运行时代码，已保存为独立安装包。不是直接与 Git HEAD 的旧实现比较。本轮未改变工作量批次、带路选择规则、输出数量或设施位置。

## 实现

### 寻路占地复用

`mpp/belt_planner.lua` 原先对每个规划设施执行世界坐标转换、碰撞框旋转与吸附，再将每个覆盖格转换回寻路网格。现在在一次同步路由中，按原型名、方向、横纵小数对齐建立占地偏移表，后续相同设施平移复用。

昂贵的坐标／形状转换次数从每个设施一次降为每种形状和对齐组合一次；占用格写入仍与格数成正比。半格、四分之一格、负坐标、四方向、非对称碰撞框和 off-grid 原型均有独立逐格转换对照。真实已有 ghost 仍使用当前 bounding_box。平移结果与原实现一样吸附到整数寻路格，保持格编号分配和占地顺序。

### 直线路径检查

预定义直线绕行通常只有三至五个拐点。自交检测由逐格字符串哈希改为轴对齐线段相交检查；每段排除已处理的起点，零长度段不重复记入。

自交检测从与路径长度 L 成正比的哈希操作改为与线段数 K 的平方成正比的几何比较，检测辅助内存从 O(L) 降为 O(K)。逐格障碍检查和最终路径记录仍保留 O(L)，没有跳过任何世界障碍。600 组确定性随机路径与逐格枚举对照，覆盖回头、重复拐点、自交和沿途障碍。

### 供电裁剪

`mpp/beacon_rows.lua` 的连通性探测使用可复用队列、访问编号和目标编号，避免每次探测都创建大型临时集合。若一个电线杆已经是某设施唯一的供电者，将其标记为必须保留；后续只会删除电线杆，覆盖计数不会增加，因此无需重复判断这个节点。

保留原有裁剪顺序、BFS 遍历顺序和搜索预算。这个优化降低重复工作和分配成本，没有替换成近似连通性判断；最坏情况下仍需进行连通性搜索。

### 矿机候选与设施处理

- 大矿机容量布局仅为可用资源位置创建矿机候选记录，不为空位、受阻位置或预留插件塔位置创建弃用记录。
- 仅调试导出时深拷贝候选评分，正常规划移除无用途的拷贝。
- 已有设施查找使用数字坐标桶，缓存静态原型分类，空桶直接返回，直接遍历候选而不复制临时数组。缓存仍按 tick 失效，实际建造实时查询。
- 新增数值形式的碰撞边界查询；渲染任务用一个数值数组保存边界，减少每个设施的嵌套表。保留原有实体盒接口，旋转、吸附和原型替换行为一致。
- 每个同步绘制批次复用 surface 方法和 force 引用；原生放置检查仍逐设施执行。中途保存的旧版嵌套碰撞框任务也可以继续运行。

## 性能结果

测试使用 17,965 格不规则大矿区、大矿机、自动并带／分带、44 路采集输出，连接 2 车头、4 货厢、双侧装货站。输出设施数和预览图层数保持不变。

### 纯计时：两个独立基线／优化进程配对

每个进程包含 8 个输出方向与镜像组合，两轮共 16 次请求／版本。关闭测试专用入口图遍历断言和快照导出，保留实际预览工作。

| 指标 | 本轮基线 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 累计脚本耗时平均 | 615.5 ms | 486.1 ms | -21.0% |
| 累计脚本耗时中位数 | 604.5 ms | 476.1 ms | -21.3% |
| 连接带路由阶段平均 | 114.0 ms | 57.1 ms | -49.9% |
| 所有请求中的最大 tick | 335.7 ms | 239.0 ms | -28.8% |

八种设置按两轮取均值后均下降，但个别单次结果有回退；最高 tick 仍超过 200 ms。这是当前机器和固定大矿区的原生脚本测量，不是完整点击到画面就绪延迟，也不代表所有矿区都会同比改善。

### 带正确性验证的首次场景

| 场景 | 本轮基线 | 优化后 | 调度跨度 |
| --- | ---: | ---: | ---: |
| 已应用矿区，首次独立车站输出 | 530.9 ms | 442.8 ms | 17 → 17 ticks |
| 刚开启车站，首次输出且重算矿区 | 1116.1 ms | 1077.7 ms | 112 → 112 ticks |

首次完整规划的候选布局阶段为 255.4 → 161.9 ms，供电布局为 127.4 → 113.0 ms，连接带路由为 128.8 → 36.3 ms。其他阶段出现耗时波动，故不能将各子项改善量直接视为最终等待改善量。首次完整规划总脚本时间只下降约 3.4%，本轮没有缩短其 112 tick 调度跨度。

一次带断言和快照的八方向运行，均值反而为 541.6 → 575.5 ms，部分阶段有较大尖峰。因此另行进行了上述两轮纯计时；保留全部原始结果，不把最佳单次成绩当作稳定收益。临时对象分配和测试断言会影响计时分布，GC 本身未直接测量，不将尖峰全部归因于 GC。

## 剩余空间

独立输出仍需处理 17,984 个设施、19,386 个图层，长距离连接仍有 14,106 个设施。将部分汇流前移到矿区出口可能进一步降低工作量，但会改变布局，需同时验证负载上下限、允许损失、输入连接与输出数限制。

同步寻路、供电布局和首次矿区重算仍可能产生长帧。下一步应同时关注这些同步阶段和 112 tick 调度跨度，避免只改善平均 CPU 耗时而未改善实际等待。
